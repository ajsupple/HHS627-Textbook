Introduction to R

R is a programming environment in which researchers can do a variety of different things. Most typically we will use R to:

1.Manage data sets 2.Clean, code data, create summary scores 3.Do statistical analyses like t-tests, regression, multilevel modeling, SEM 4.Create graphs, tables, and figures

But R can do a number of other tasks for us like reading OSF pages, scraping internet sties, renaming files, and converting files to PDFs.

Why R?

  • It is Free!
  • It is open-source which means that anyone can access, add to R and its numerous packages
  • It uses a simple programming language developed by experts, you can see all source code (unlike some proprietary stats packages)
  • This all means that there are new additions to R all the time to keep up with state-of-the-art changes in statistics

Who will enjoy R the most?

  • People who like programming!
  • People who enjoy learning new code, exploring what R can do
  • Those looking to streamline work time by using convenience features related to creating tables in APA style

Benefits of learning all that R can do for academic researchers

  • Saves time and energy when creating reports
  • Fewer mistakes transcribing output to tables and figures
  • Can access anywhere (unlike networked software)
    • Makes it faster to analyze data
    • All analyses we want to do are possible with R

What steps do you take to get started?

Download R from https://cran.r-project.org/

Download RStudio from https://posit.co/downloads

Find videos, tutorials, free books on GitHub, AIs are pretty good with R code

What is the difference between R and RStudio?

R is the programming language in which we write code and execute commands. RStudio is a GUI (graphical user interface) that simplifies many of the basic tasks (e.g, reading in an SPSS file, installing packages, viewing plots) that we typically want to accomplish with R.

RStudio is what we will predominantly use in class and there are four sub-windows in R Studio:

  • Console for running code immediately
  • Script editor for saving code or running chunks of code
  • Environment pane showing objects you’ve created
  • Files/Plots/Help pane for outputs and documentation

Beyond the advantage of being able to more easily do basic tasks than with R, RStudio also has syntax highlighting, code suggestion/completion, spellcheck, and some smart coding routines

Packages and Functions

There is Base R which has a number of functions

Cleaning, Screening, and Dealing with Missing Data

Typically we organize and store data in some sort of spreadsheet. SPSS users for example might read in data from an excel spreadsheet or manually type in data.

Data in this instance refers to numeric values that represent things like participants:

  • Age, gender, race-ethnicity
  • Levels of stress, depression, motivation to exercise
  • ID number identifiers for participants, families, schools, couples, neighborhoods

Regardless, data is often entered into a spreadsheet that really could use any software. Excel, notepad, SPSS, for example, and R can read in most any spreadsheet formats.

For new data, a wise initial step before getting into more sophisticated analyses is to use some basic descriptive statistics to screen one’s data

Other Tranformations

  • Let’s say that anxiety item 4 was in need of reverse scoring.

  • This often arises in cases where items have different “valence” in terms of positive or negative valence.

    • For example: anx1 asked participants “How often have you experienced overwhelming worry over the past week?” with response options of: Never, Rarely, Sometime, Often, Very Often
    • anx4 asked “Have you been able to easily relax in the past week?”.
    • Note that a score of ‘5’ for one item would indicate frequent experiences of anxiety, but a low anxiety on the other.
    • In cases like this, items that are counter to the desired valence - in this case greater frequency of anxiety - would be reverse coded so that an overall summary score doesn’t combine high and low anxiety across the items
    df_csv$anx4 = 5-df_csv$anx4 # This converts item 4 scores from: 4 --> 1, 3 --> 2, etc

    WarningWhat Are Outliers?

An outlier is an observation that is unusually distant from the bulk of the data — either extremely high, extremely low, or both (in multivariate settings). Outliers may reflect:

  • Data entry errors (e.g., age coded as 999)
  • Measurement error (e.g., equipment malfunction)
  • True but rare observations (e.g., a legitimately high income in a low-income sample)
  • Violations of study protocol (e.g., participant who didn’t follow instructions)

How to Detect Outliers

Univariate (single variable): -

  • Visual: Boxplot, histogram, scatterplot — look for points far from the main cluster

  • IQR method: Mark as outlier if value < Q1 − 1.5×IQR or > Q3 + 1.5×IQR -

  • Z-score method: Mark as outlier if |z| > 3 (more conservative: |z| > 2.5) -

  • Range checks: Compare to known valid ranges (e.g., age should be 0–120)

Multivariate (multiple variables):

  • Mahalanobis distance: Measures how far a case is from the centroid of all variables combined

  • Cook’s distance: Identifies cases with high influence on regression coefficients

  • Leverage + residuals: Cases with high leverage and large residuals are flagged

# IQR method
df <- tibble(age = c(25, 30, 28, 32, 999, 27, 29))  # 999 is an outlier

Q1 <- quantile(df$age, 0.25)
Q3 <- quantile(df$age, 0.75)
IQR <- Q3 - Q1
lower_bound <- Q1 - 1.5 * IQR
upper_bound <- Q3 + 1.5 * IQR

outliers <- df %>%
  filter(age < lower_bound | age > upper_bound)

# Z-score method
df <- df %>%
  mutate(
    z_age = scale(age)[, 1],
    is_outlier = abs(z_age) > 3
  )

:::: ## Coding Categorical Variables

  • Nominal: no inherent order (e.g., race/ethnicity, program site, referral source).
  • Ordered categorical: ordered categories without equal spacing assumed (e.g., Likert items, severity stages: mild/moderate/severe).
  • Dummy coding: reference group = 0, comparison groups = 1; coefficients interpreted relative to the reference.
  • Effect coding: groups coded -1/1; coefficients interpreted relative to the grand mean.
  • Note that we will get into coding specifics in R when we run analyses…
WarningCommon Pitfall

Numeric-looking codes (1 = Male, 2 = Female) get accidentally treated as continuous in R if not explicitly converted to a factor — this silently corrupts downstream models. Also, there are many good reasons for why binary variables should be recoded to 0/1. For example, got divorced = 1, did not get divorced = 0 as opposed to 1 and 2.

  • Easier interpretation of intercepts in regressions
  • Easier interpretation when doing product terms for interactions
  • Mean is actually meaningful (will be percentage of participants in 1 category)

ImportantDiscussion Questions

We need to be really careful with nominal IVs. Say for example I want to see if there is greater participation in blood pressure screening at Urban Health Clinics, Rural Clinics, or via TeleHealth visits (using home BP monitor)

I would most likely have a variable titled “Clinic Type” that has values of 1, 2, and 3 that represent Urban, Rural, and Telehealth, respectively

In an ANOVA, that isn’t much of a problem because the RQ is: Are there differences in participation across three clinics? In Multiple regression, however, we are asking: Is a one level increase in clinic type (meaningless) associated with greater BP screening participation

In a case like this we need to dummy code site type. Will come back to this later…

Data Structures: Wide vs. Long

Wide format — one row per subject, repeated measures spread across columns:

id score_t1 score_t2 score_t3
1 12 15 18
2 9 11 10

Long format — one row per subject-time observation:

id time score
1 t1 12
1 t2 15
1 t3 18
2 t1 9
2 t2 11
2 t3 10
Note

ggplot2,

Most cross-sectional data or SEM-type data are going to be “wide” format - so there is one row per participant, and each column represents a different variables. If the data are repeated measures/longitudinal, each variable would just be a score at a particular time point

Many “mixed-effects” models (for example the lme4 package) will read in long-format data frames. So there will be multiple rows per participant and there often need to be more than one ID variable. Then there are columns for each variable and the rows represent different scores that are “nested” in teach participant.

More on Getting Data into R

Most of my experience reading in data has to do with bringing data in from some sort of spreadsheet like in an excel or SPSS file.

There are BaseR commands to read in .txt files like:

  • df <- read.csv(“myfile.csv”) : For comma separated files (csv)
  • df <- read.delim(“myfile.txt”) : For .txt or text files with tab delimiters (spacing)
  • df <- read.table(“myfile.txt”, header = TRUE) : For generic text files
  • header = TRUE means that the first row includes column (variable) names

Packages with functions to read in data, often from specific software

  • Tidyverse has a package called “readr” - name of the dataset goes in the ()

    • read_csv() CSV
    • read_tsv() Tab-delimited
    • read_delim() User-specified delimiter
    • read_table() Fixed-width text tables
    • read_fwf() Fixed-width files
    • read_rds() will explain that later…

Notice that there are very similar commands/functions here, the . and _ differentiate the package and what these do… easy to get confused.

  • The haven Package - note, no caps in ‘haven’

    • read_sav() # SPSS
    • read_por() # SPSS portable - usually has been converted first
    • read_dta() # Stata
    • read_sas() # SAS
    • read_xpt() # SAS transport

  • You may also come across the foreign package, older probably less used

    • read.spss() # SPSS
    • read.dta() # Stata

Data Frames

Datasets are typically stored in data frames. R will refer to data frames has having Rows and Columns.

Typically in a wide-format dataset, each person/case/subject/participant/unit will represent a row, while each variable will be in a column. It is helpful to remember that terminology because we will sometimes reference columns and rows.
